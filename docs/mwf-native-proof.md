# Native Mountain Weather Forecast (local proof)

This branch rebuilds NWAC's Mountain Weather Forecast (MWF) as a first-class AvyWeb feature: a Payload collection owns storage, a custom admin view hosts the authoring grid, the public site renders it directly with no cross-service hop, and AvyWeb serves both a clean read API and a legacy-shape shim for installed Avy app versions. It is a proof-to-pitch, built side-by-side with the in-flight dashboard-v2 + products-api implementation (Rachel's work) that it would replace for NWAC; nothing here is team-agreed, and dashboard-v2's MWF remains the fallback for the 2026-27 season.

The feature is NWAC-gated behind a per-tenant Settings flag but generic-shaped: all center-specific content (zones, points, model sources, extended-snow-level zones) lives in per-tenant Settings config, so a second center is a config exercise plus deferred structure work, not a rewrite.

## Key differences from the dashboard-v2 / products-api implementation

**Storage.** products-api stores MWF as `product_type='weather'` rows in the shared `national.bulletin` table, with issuance/revision/service_date/supersedes buried in an untyped JSONB variant envelope (`weather_data`) — the design the team itself flagged as implicit and gotcha-prone. Here every field the workflow queries or guards on is a typed, indexed column on a dedicated tenant-scoped collection; only the seven content sections (which nothing queries into) and the publish snapshot live in JSON. Same envelope idea, explicit spine.

**Workflow.** The lifecycle semantics are a deliberate 1:1 port: published rows immutable, corrections as new drafts with revision+1 pinned to the parent slot, "current" as the newest visible non-draft chain head, withdrawal of a live head hiding the whole issuance (a PM withdrawal falls back to the AM, never an older PM revision), scheduled publish via future issue time, hard-delete for drafts only. Two enforcement differences: the invariants are also enforced in collection hooks so no write path can bypass them, and the atomic publish guard serializes per-slot with an in-process lock (adequate for single-instance SQLite; products-api uses a Postgres advisory lock — a multi-instance deploy would need the DB-level equivalent).

**Authoring.** A React port of the editor inside a custom Payload admin view (embed-generator pattern), reconciled against dashboard-v2 PR #158's final state: morning window through Night 2, per-table sub-windows (temps over the first two periods, AM precip through Day 2, six AM snow-level blocks), 7am AM default, optional extended synopsis, over-precise QPF flagged, preserved-cells stash so config changes never silently drop entered values, and the same section order/scrollspy layout. Differences kept deliberately: entry cells are text inputs with arrow-stepping and snap-on-commit rather than datalist comboboxes (equivalent behavior), and discussion fields are plain text rather than rich text.

**Model guidance.** Ported to TypeScript: the WRF3UW1 1.33km point JSON for QPF, the Airfire UWFS zone summaries for temps/winds, and the GRIB2 QPF sources (HRRR 3km + NBM ~5km seeded; RRFS pending a confirmed live URL), driven entirely by Settings config (the zone-code map lives on the zones' `airfireZoneId` rather than per-model config). The keep-last-good cache and newest-available-run selection match products-api; refresh is an hourly Vercel cron plus on-demand rate-limited refresh at editor load, and the artifact of record is a durable `mwfGuidanceArtifacts` row per (tenant, table) with the in-process map as a hot layer — the serverless equivalent of products-api's disk persistence, so the cron's build survives into other instances and keep-last-good survives cold starts. The GRIB2 decode spine lives in `src/services/mwf/grib2.ts` — cycle selection by sentinel-hour `.idx` probing, raw-line `recordMatch`/`exclude` matching, byte-range record reads decoded with `@azohra/meteo.grib` (pure TS, version pinned), cached nearest-gridpoint sampling, and END-hour `(start, end]` accumulation into the four 12h periods, unit-tested against a recorded HRRR record — and is wired into `buildQpfGuidance` as the `grib2` sourceType (per-hour failures surface as loud `errors` on the model meta; a loaded grib2 model's 6-hourly cycle drives artifact staleness). Model rows carry an `active` toggle (products-api's `enabled is not False` semantics: only an explicit false disables); switched-off models are not fetched and show no column. The editor re-polls guidance every few minutes in-session (visibility-gated; the overlay is replaced wholesale — cleared then re-applied — so a new model run or a mid-shift deactivation shows up without a reload, and entered values are never touched). Still not ported: the settings-page "Test source" probe.

**Public reads.** The native weather page reads Payload directly through a local source adapter (no HTTP hop) and the archive renders from each row's publish-time snapshot of config and structure, so history is immune to later config changes. The route gate for a center is the Settings flag, not the NAC `platforms.weather` capability (hardcoded false for NWAC upstream). The Avy app contract is proven two ways: the app's zod schema ported verbatim as an executable contract, and live goldens pinning the real wire shape — which surfaced semantics the design docs didn't know (zone-scoped trimmed two-period window, weekday period labels, the PM tonight slot as `4-night`, and that the legacy backend is now a WordPress plugin rather than Django).

**Known parity gaps** (candidates for the pitch conversation, not blockers): legacy precip bucket strings ("LT 0.10") and wind-speed ranges ("10-20") are emitted as plain numbers by the shim (schema-valid either way); imported archive rows keep those legacy strings verbatim and render them as blanks in numeric cells; creation timestamps accept a center timezone but AvyWeb has no per-center timezone Settings field yet, so drafts stamp server-local.

## Operating it

Local dev needs `ENABLE_LOCAL_MIGRATIONS=true` while the dev database is migration-managed. The flag defaults off for every tenant except seeded NWAC; toggling it per tenant is super-admin-only in Website Settings → Features. Guidance refreshes hourly via `/api/cron/refresh-mwf-guidance` (Vercel cron in `vercel.json`). The archive imports with `pnpm payload run ./src/scripts/import-mwf-archive.ts -- --from YYYY-MM-DD --to YYYY-MM-DD` (idempotent; resumes after interruption). `src/scripts/apply-nwac-mwf-config.ts` applies the seeded NWAC config to an existing database without reseeding.
